# 水族馆水槽投喂与设备点检系统

零依赖（Node ≥ 22.5 内置 `node:sqlite` + `http`）的水族馆运维系统：水槽、生物批次、饲料批次、投喂计划（版本化）、投喂任务（扫码幂等）、过滤设备点检、水质读数、异常观察与处置、交接日志。

## 单条启动命令

```bash
./run.sh            # 或 npm start
```

首次启动自动建库并生成演示数据（**投喂、停机、复核样例**），访问 http://localhost:8080 。
常用参数：`--port 9000` 改端口，`--reseed` 清空并重建演示数据，`--db <path>` 指定数据库文件。

## 测试

```bash
npm test            # node --test，12 个用例
```

覆盖：剂量边界（0/负数/下限/上限/非数字）、饲料扣减（完成才扣、余量不足、恰好扣尽）、计划版本（历史保留、已执行任务快照不重算）、重复扫码（幂等不重复扣减）、异常冻结（点检未通过冻结计划、复检解冻），另含漏投、饲料过期、补录读数校验、拒食异常。

## 业务规则

| 规则 | 实现 |
| --- | --- |
| 饲料扣减 | 仅在扫码完成投喂任务时扣减批次剩余量（条件更新防超扣）；生成任务、漏投、冻结均不扣减 |
| 计划版本 | 变更生成 version+1，旧版本 `superseded` 保留；已执行任务保存剂量/批次快照，绝不重算 |
| 重复扫码 | `scan_token` 唯一，已完成任务再次扫码返回幂等结果，不重复完成、不重复扣减 |
| 五类异常 | 水温越界 / 过滤器停机 / 生物拒食 / 饲料过期 / 漏投，各自生成异常 + 处置任务（去重键防重复） |
| 点检冻结 | 点检未通过 → 设备停机 + 关联投喂计划与待执行任务冻结；复检通过 → 自动解冻并解除异常 |
| 补录读数 | 必须保留采集时间（`collected_at`）与设备编号（`device_id`），否则 422 |
| 到期提醒 | 进程内调度器（15s）：投喂临期、处置到期/逾期、饲料临期 7 天 |

## 技术栈与存储

- **SQLite**（`data/aquarium.db`）：计划、任务、读数、异常、交接等全部结构化数据
- **本地文件**（`uploads/`）：点检照片，`POST /api/uploads` 二进制上传
- **进程内调度**（`src/scheduler.js`）：任务生成、漏投判定、过期检查、提醒刷新
- 前端：`public/` 原生 SPA，海蓝 `#0b6fa4` / 薄荷绿 `#1fb99a` / 珊瑚色 `#ff6f61`

## 六个交付页面

1. **水槽总览** — 平面水槽图定位设备（点击圆点直接点检），异常水槽顶部色带 + 文字徽章双标识
2. **投喂日历** — 按时段分组，剂量刻度条（对比水槽上限）、剩余时间倒计时、扫码完成
3. **饲料批次** — 批次有效期、剩余量条、临期/过期标识，新批次登记
4. **设备点检** — 通过/未通过大按钮、备注、照片上传，未通过冻结提示
5. **异常观察** — 五类异常卡片 + 处置任务闭环，拒食观察录入
6. **交接日志** — 交接自动附带运营摘要（未结异常/待处置/停机/冻结/待投喂）

## 演示样例（种子数据）

- **投喂样例**：T-01 昨日 2 次完成（已扣减）+ 1 次漏投；今明两日任务已排程
- **停机样例**：T-02 过滤器 `FLT-T02-1` 点检未通过 → 停机、计划 v2 冻结、处置任务待办
- **复核样例**：T-03 补录读数 29.4℃ 越界 → 复核处置任务；T-04 拒食观察；`FEED-ALG-2508` 已过期
- 生物编号 `BIO-2026-0xx`、读数设备 `PROBE-T0x-x` 均为演示数据

## API 摘要

```
GET  /api/overview                     水槽总览（设备/计划/今日任务/未结异常）
GET  /api/calendar?date=YYYY-MM-DD     投喂日历
POST /api/tasks/complete               {scan_token, operator} 扫码完成（幂等）
GET|POST /api/plans                    计划版本查询 / 保存新版本
GET|POST /api/feeds                    饲料批次
GET  /api/equipment                    设备（含最近点检）
POST /api/inspections                  点检（fail 冻结 / pass 解冻）
POST /api/uploads                      点检照片（二进制 + X-Filename 头）
GET|POST /api/readings                 水质读数（补录须 device_id + collected_at）
GET  /api/anomalies?status=            异常列表（含处置任务）
POST /api/anomalies/:id/ack|resolve    知晓 / 解除
POST /api/handling/:id/done            完成处置
POST /api/observations/refusal         拒食观察
GET|POST /api/handovers                交接日志（GET /api/handovers/digest 取摘要）
GET  /api/reminders                    未确认提醒（POST /api/reminders/:id/ack）
```
